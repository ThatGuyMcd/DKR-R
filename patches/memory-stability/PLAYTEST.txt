DKR-R v1.0.10 Memory Playtest 1

This is a test build for the missing HUD and guest memory allocation failures
reported in v1.0.9 and v1.0.10. Keep your current release folder as a fallback.

The original main pool was still ending at 4 MiB in ordinary sessions, while
the runtime already maps expansion RAM and keeps extra racer models resident.
This build admits the known original pool up to 0x807E0000 at initialisation.
It leaves a 128 KiB upper guard. Existing custom-session admission is unchanged.
No allocator, delayed-free lifetime, model quality, launcher layout, save routing,
or spectator music/race-start fix was replaced. HUD failures now log heap figures.

Everyone in an online lobby needs this same build. Its peer identity changed
because the main pool's addresses are part of the shared simulation state.

Please try the races that failed, then repeatedly restart races, change tracks,
return to Track Select, and try a modded lobby with a spectator. Check lap/time/
banana digits, audio and the spectator picture throughout. If anything fails,
send runtime.log and runtime-previous.log from each affected machine, together
with the track, enabled mods and action immediately before the failure.

Verification uses the actual final allocator bodies with synthetic RAM, both
ROM revisions, fragmented allocation failures before/after, 5,000 unload/reload
cycles, delayed frees, checkpoint restore and the upper guard. The prior online
regressions are also retained. No ROM, game, RSP or live lobby was run here.
This is not a guarantee against every crash or an unlimited mod memory budget.

Do not publish these files as a replacement stable v1.0.10 auto update yet.
