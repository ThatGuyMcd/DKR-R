DKR-R v1.0.7 beta 10 - Shared saves and Save Manager repair

ONE PERSONAL SAVE
Normal offline play now uses the same Adventure with or without character,
track and gameplay code mods. Changing a mod or its options no longer creates
another Adventure file. Your three original slots are still there.

Older mod-set files are kept. Before the first shared-save launch or replacing
progress, DKR-R preserves a migration inventory and image copies. It does not
guess which playthrough you want or merge balloon totals. If an older mod-set
save has the progress you want, open Save Manager > Backups & Recovery and
choose Use as personal save. Check the slot preview before confirming.

MAX OUT AND UNLOCKS
Max Out Entire Save completes all three slots and unlocks Drumstick, T.T. and
Adventure Two. Max Out This Adventure completes just the selected slot, plus
the shared unlocks. Unlock All Racers and Modes keeps your Adventure progress.
These actions now save when confirmed; you do not need to press Apply again.
Initials and personal-best times are preserved. Empty completed slots get DKR
initials. Known progression cutscenes are marked seen without converting an
Adventure One slot into Adventure Two.

Ordinary manual editor changes still use Apply Changes. Applying checks that
the on-disk save has not changed since the draft was loaded, backs it up and
reads the result back. If the draft is out of date, discard it and reopen the
editor. A completion popup changing the draft is no longer treated as a save.

SAVE MANAGER
Your Save manages the same personal Adventure normal gameplay loads.
Backups & Recovery includes old mod-set copies, automatic history, migration
copies and supported portable locations. Identical copies are grouped for
display only; nothing is deleted. Larger inventories have Load More.
Online Saves manages the separate host Adventure and surviving session copies.
Controller Paks have individual backup, import and export actions again.
Imports ask before replacing progress. Checksum repair is explicit, and the
unchanged original is preserved. Repair cannot reconstruct damaged progress.
Damaged images can be exported as-is for recovery instead of being discarded.

CUSTOM RECORDS AND TRANSFERS
Added .dkrmap course records use a versioned companion file, keyed by stable
course identity and vehicle, rather than being packed into the original EEPROM.
Disabling a course does not erase its stored records. Legacy replacement courses
still inherit their native carrier's retail record slots; this is not a new
record format for full ROM hacks or a conversion of old session-only records.
New .dkrsave bundles include the personal EEPROM, present Controller Paks and
the custom-record companion when available. Older version-1 bundles still load.
Bundle imports preserve originals in a typed recovery journal. An interrupted
replacement is recovered before the next launch/import. A failed recovery is
reported rather than claiming everything was rolled back successfully.

ONLINE AND DEVELOPMENT
The host has one durable online Adventure, independent of the mod-list hash.
Continue is the new default. The first host session copies a valid personal save
when available, otherwise starts fresh. Copy Personal Save and Start Fresh are
explicit alternatives; they replace the host Adventure at activation, with the
previous image retained. Old mod-specific online saves can be chosen manually
from Online Saves. Clients' personal Adventures are never overwritten.
Rollback custom-record writes use confirmed frame journals, not speculative RAM.
Development tools remain isolated. Incompatible save-layout conversions still
need a dedicated adapter; this does not enable arbitrary EEPROM formats.

DEVELOPMENT SAVE CORRECTION
The first beta 10 package could show a completed personal save in the manager
but load zero balloons with Dev Menu enabled: a missing development EEPROM was
being initialised blank. New offline development copies now inherit saved
personal progress, without letting developer tools write to the personal file.
Existing development copies are not silently overwritten. To refresh one,
confirm Copy Personal Save to Development in Save Manager, then launch with
Dev Menu enabled. Its previous development image is preserved. This copies
saved progress, not an unapplied editor draft. Startup logs now name the actual
save owner, path and slot totals so a different write target is not hidden.

EVERY ONLINE PLAYER MUST USE THIS BUILD
The confirmed-record journal changes the rollback build contract. Do not mix
beta 10 with beta 9 or earlier in the same session.

PORTABLE MODE
Portable and normal user-data folders remain separate locations. Switching
portable mode does not silently move files. Recovery now includes the public
application's portable folder as well as the known old runtime locations.

BUILD STATUS
This is a playtest build for the owner to assess. Compilation and static
source/package inspection are not gameplay or save-recovery acceptance.
No game, launcher, save mutation test, replay test or online session was run
while producing this build. Keep an external copy of your data before testing.
No ROM, personal save, account data or signing key is included.
