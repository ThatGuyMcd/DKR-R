# ModernCamera++ implementation status

The flat-screen path is connected end to end: import/approval, presentation-only
activation, retained snapshots, local actions, mod callback, private scene draw,
RT64 decode, native fallback and F7 settings with asynchronous persistence.
The old active Modern camera replacement and its input rewriting are removed
from the staged source. Native Original/scripted cameras and clearance remain.

## Connected components

| Component | Boundary |
| --- | --- |
| SDK and mod | Versioned POD ABI; portable MIPS package; Original/chase/bonnet/first/comfort/cinematic; bounded effects, zoom, rear view and vehicle tuning. |
| Executor | Private memory only; one provider; 250,000 instructions, 256 services and eight bounded queries per callback; local quarantine. |
| Snapshot reader | US v1.0/Rev A retained images; actual racer identity, vehicle, original camera and scene/cut ownership. No concurrent CPU read. |
| Collision | Copied static triangles, broad phase, swept volume and budgets. No claimed moving-platform/door adapter. |
| Scene compiler | 146 closed per-view native draw routines per revision; checked memory, 6M operation cap, private command/matrix/vertex/triangle pools and C-only fault fence. Frozen weather/lens-flare drawing, no full scene/logic/audio tick. |
| Decoder | One working owner, bounded 16 MiB command limit only during authorized camera decode, original 8 MiB otherwise; restore before canonical HUD/next view. |
| Presentation | View-local hiding, scene/object matrix identities, cut snapping and topology-keyed wave identities. No generic vertex interpolation. |
| Controls | Dedicated remappable camera actions from existing SDL2/SDL3 polling; no extra controller probe; menu/held-button suppression, local mouse capture and short-tap latching. |
| Editor | Shared Paddock controls, controller navigation, grouped fields, four local profiles, presets, Apply/Revert/Reset/Save; existing on-screen keyboard for text. |
| Storage | Existing bounded LibraryJobs worker; acknowledgement checks the exact saved document/digest. No UI-thread file writes. |
| Online | Separate presentation admission and fingerprints; local racer/physical/profile mapping. No camera writes to rollback RAM, rules, saves or synchronized input. |

## Not enabled in this playtest

True OpenXR eye scene/HUD output, head-wall comfort, unrestricted inspection and
rider-only hiding still need implementation. Their renderer capabilities stay
off. The OpenXR/device-integration foundations are separately compiler-checked,
not distributed as working VR. Ordinary bounded right-stick camera orbit and
rear view are available without claiming unrestricted inspection.

## Evidence and qualification

Fresh stage receipts verify every copied first-party source against its accepted
portrait baseline, authored transforms and pinned reference symbols. Generated
private draw closures are derived from the accepted generated inputs without
editing them. The dependency exception is constrained to four separately staged
device files and is not needed by the flat-screen packages.

Windows/MSVC and Linux/GCC compiler/linker results and package hashes accompany
the delivered build. There is no gameplay, replay, unit, mod-execution, visual,
headset or performance acceptance run by the agent. The user performs those
checks. The accepted previous packages are preserved.
