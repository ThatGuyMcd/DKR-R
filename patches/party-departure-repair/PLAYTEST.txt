DKR-R 1.0.9 - Online departure repair playtest 12
===============================================

Use this COMPLETE fresh package on every machine. Do not mix playtest versions
or copy only the executable over an older folder. Saves and installed mods stay.

The working Playtest 11 startup/checkpoint fix and five-second countdown remain.
This build repairs how spectator-capable parties handle someone leaving:

* A client closing DKR-R sends an authenticated leave notice and briefly waits
  for the host's receipt before retiring its connection (maximum 400 ms).
* The host removes the departed member, updates the roster and releases their
  lobby place. A departing racer stops the shared match safely and returns the
  remaining members to the lobby; it does not silently leave a phantom racer.
* A spectator leaving removes that viewer without ending the race.
* Both party leave and generic authenticated Disconnect notices reach the same
  party-specific handling. Returning to the launcher is recognised too, while
  keeping that member in the lobby for the next game.
* A force-close or network loss that cannot send a goodbye is detected by the
  current transport closing or by ten seconds without authenticated traffic.
  A momentary recoverable WebRTC Disconnected state alone is not terminal.
* New departure/close logs distinguish notice acknowledgement, transport loss,
  silence timeout and return to lobby. They contain no keys or peer addresses.

Please check: two racers start and play; close the client application; the host
should return safely with the client removed. Restart/rejoin and start again.
Also check client return-to-launcher (member remains), spectator exit (race
continues), host exit (remaining clients leave safely), and abrupt connection
loss (allow ten seconds after the last authenticated packet).
