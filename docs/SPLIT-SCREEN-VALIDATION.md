# v1.0.5 Beta 1 split-screen presentation validation

Date: 7 September 2026. This is a presentation-only rebuild, not a new online protocol.

## Changes and evidence

- F3DDKR combined world MVPs retain their existing model/interpolation identities.
  The bridge gives split world passes a separate, scoped projection-aspect policy,
  then restores it before HUD draws. Mirrored viewport scales retain their sign.
- Only framebuffers tagged by the split-viewport marker have their aggregate
  native-width scissors normalised to 320. Per-draw expanded scissors remain intact.
  Previously their expanded union could be interpreted as a wider native framebuffer,
  giving texture rectangles a different horizontal scale from ortho sprites.
- Three/four-player race-position entries 0/1 and weapon entries 2/49 move outward
  according to their owning HUD quadrant. Banana counters and other HUD entries
  retain their established placement. Width, height and texture coordinates are
  not scaled to accomplish this translation.
- A first counter candidate used extended LEFT/RIGHT origins. That did not move
  the numbers: `rt64_renderer.cpp` deliberately selects `extAspectRatio=Original`,
  and RT64 maps that to `extOriginPercentage=0`. The corrected implementation
  applies equal signed horizontal rectangle offsets within the element's scope,
  without enabling global extended origins. Re-running the original positioning
  test with the actual zero setting reproduced the reported failure before the fix.
- Unit-scale rank textures normally enter a deferred batch. They use the existing
  immediate unscaled drawing path while the per-element offset is active. The
  override is restricted to effective scale exactly 1 and colour `0xFFFFFFFE`.
  Animated/scaled frames retain that original alpha sentinel: the decomp's
  `rcp_dkr.c::texrect_draw_scaled` selects XLU with alpha 254 but OPA with alpha 255.
  Applying the unit-scale override to animation frames exposed grey backgrounds;
  the final candidate preserves the original animated transparency path.
- The optional three-player black panel is bracketed at the actual fill in
  `divider_draw`, after retail decides between the map/panel and T.T. camera.
  That fill alone extends to the expanded right edge. Its original centre and
  vertical bounds are retained. Full-width backgrounds and T.T. camera selection
  are unchanged. Both ROM revisions use verified patch-pipeline hook addresses.

## Verification

- Windows Release: all 64 project tests passed, 123.62 seconds.
- Linux Release (Ubuntu 24.04 under WSL): all 64 project tests passed, 16.68 seconds.
- The split-screen test uses the pinned renderer's RSP matrix groups, projection
  processor and rectangle conversion. It covers 40 combinations of 3/4 players,
  normal/mirrored horizontal scales and 4:3, 16:10, 16:9, 21:9 and 32:9 host ratios.
- HUD policy checks cover layout/player/element gating and animated scale/alpha
  combinations, including preserving existing fading colours.
- Native Windows DX12, US v1.0: the user confirmed corrected three-player world/HUD
  proportions, weapon placement, then outward rank placement. After the final
  transparency correction the user reported: "That did the trick perfectly!"
- The native check also showed the optional map panel and T.T. camera, rather than
  replacing the fourth quadrant unconditionally with black.
- Final tested Windows executable SHA-256:
  `F2A38A098F48AE48CDA96EB8ED5E44B869C2DBDD2C1A49D631D4166B031DDD84`.
- Build/test/package logs are retained locally in
  `build/split-screen-validation-20260907`. Packages are staged separately in
  `dist/split-screen-v1.0.5-beta.1-20260907`.

## Protected scope and qualification limits

- No RT64, N64Recomp, N64ModernRuntime or decomp dependency source was edited.
  Generated game functions were regenerated by the patch pipeline, not hand-edited.
- Online code, rollback behaviour, save isolation, controller routing, launcher
  implementation and existing shadow fixes were not modified by this pass.
- The earlier package in `dist/track-performance-v1.0.5-beta.1-20260907` remains
  unchanged and hash-verified. Its source/package snapshot is retained at
  `build/rollback-pre-split-screen-20260907`.
- Automated four-player/aspect-ratio coverage is not a claim of complete native
  four-controller, Vulkan, US v1.1 or Steam Deck gameplay qualification. Those
  configurations should still receive native playtesting; Linux build/tests alone
  do not establish Steam Deck visual or performance results.
