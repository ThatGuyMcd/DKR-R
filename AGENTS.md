# Working in DKR-R

Guidance for AI coding agents (Codex, Claude Code, Cursor, Copilot and others).
`CONTRIBUTING.md` says the same things for people; this file is the short,
strict version.

## The pattern (non-negotiable)

- Edit first-party code in place: `runtime-recomp/` (including `runtime-recomp/cmake/`), `modding/`, `scripts/`, `docs/`.
- Never create `patches/<name>/` for first-party changes. `patches/` holds only third-party patch sets registered in
  `patches/manifest.json` against `extern/`. No `*.cmake`, no `*.py`, no `native/` under `patches/`.
- Never stage, copy, string-replace or swap sources at configure or build time. If you find yourself writing
  `pipeline.py`, `transforms.py`, `once()`, `region()` or `set_target_properties(... SOURCES ...)`, stop.
- Generated guest code is hooked only through `runtime-recomp/guest-hooks/hooks.toml` (applied by
  `scripts/guest_hooks.py`), except the two named owned-engine input stages, `scripts/save_layout_pipeline.py`
  (save-layout) and `scripts/character_portrait_pipeline.py` (portrait), which feed the owned payload byte for byte
  (`scripts/prepare_payloads.py` runs them). Never rewrite `RecompiledFuncs`, `funcs_*.c` or `guest_*.c` from any
  other script.
- Symbol tables come from `runtime-recomp/symbols/*.toml` (generated by `scripts/gen_guest_symbols.py`). Don't
  hard-code addresses.
- Online or simulation changes that break cross-play need a deliberate edit to
  `runtime-recomp/src/game/netplay/legacy_identity.hpp`, approved by both owners. Never splice a digest into an
  identity string anywhere else.
- Third-party fixes: a `*.patch` under `patches/<dep>/` plus a `manifest.json` entry with its sha256. Never vendor a
  modified translation unit.

> `architecture/pattern-guard-baseline.txt`; the guard tolerates them and fails

## How to add a feature

1. Pick or create a module directory under `runtime-recomp/src/game/<module>/` (see `docs/ARCHITECTURE.md`).
2. Register settings, pages and owned services in the registries instead of patching literals.
3. Add tests next to the existing ones in `runtime-recomp/tests/` (flat, named `*_tests.py` for tooling tests).
4. Run the checks below before opening a PR. CI runs the same.

## Verification you must run

- `python3 scripts/check.py --suite guard` before claiming any task done. This is mandatory for every agent,
  with or without hooks.
- `python3 scripts/check.py --suite guard,tooling` after changing scripts, CMake or tests.
- `pre-commit run --files <changed files>` for format and lint, if the git hooks are installed.
- `cmake --preset host -S runtime-recomp && cmake --build --preset host && ctest --preset host` before claiming a
  C/C++ change done (`CMakePresets.json` lives in `runtime-recomp/`, so pass `-S` or `cd` there).

On Windows use `py -3` or `python` in place of `python3`.

## Agent hooks

Claude Code (`.claude/settings.json`) and Codex (`.codex/hooks.json`) run the same scripts from
`scripts/agent_hooks/`: the pattern summary at session start, a pre-edit pattern guard that blocks a violating
write, a post-edit lint report that never rewrites your files, and a stop check that refuses to finish while the
session has added a guard problem. Codex loads project hooks only once the project is trusted and the hooks are
reviewed in `/hooks`. The hooks are fast feedback; the git pre-commit hook and the required CI checks are the gates.
Don't disable or route around any of them.

## Things that are not source

- Receipts, audits, "contracts" as file hashes, per-feature `package.py`. Release notes go in `CHANGELOG.md`.
- Playtest and investigation notes go in `docs/notes/<date>-<topic>.md`. They are welcome there; they are not build
  inputs.

## Pinned bytes

Some files must keep their exact bytes; `scripts/check_pinned_bytes.py` (a pre-commit hook) fails if they change.
Never reformat or "tidy" them:

- `*.patch` files listed in `patches/manifest.json`, and `modding/reference-us-v*/`.
- Until the fold deletes the 1.0.7 source capsule: everything under `runtime-recomp/src/` and
  `runtime-recomp/tests/replay_probe/` that the capsule pins as a base. Real code changes there are fine; formatting
  passes and whitespace fixes are not. On the fold branch, the bases the fold rewrote are listed in
  `scripts/fold/released-bases.txt`, which only `scripts/fold/apply_closure.py` writes; never add a path by hand.
